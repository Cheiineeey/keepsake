# 07 · 另外几种收藏

> 泡泡库之前，我们已经有好几种收藏在用了：单句、思考链里的一句、多句做成一张卡、AI 自己的珍藏。它们都还在，泡泡只是挂在旁边的一种新看法。这一章把它们各自怎么做、踩过什么写出来。

## 为什么有两种

我们的聊天有两种节奏。长聊天，一条消息就是一大段，想留的往往只是里面一句，所以有单句收藏，按气泡收、选几个字收都是为它做的。短聊天像发微信，一句一个气泡，一句单拎出来没头没尾，想留的是来回那几句，所以有多句收藏，一个个勾，排成一张卡。

先看你们平时怎么聊，再决定先做哪种。

## 先说一张表

这几种全用同一张 `treasures`，没有每种开一张表：

| 字段 | 干什么 |
|---|---|
| `quote` | 存下来的那段字 |
| `role` | 这句话是谁说的：`user` / `assistant`，多句卡是 `dialogue` |
| `collector` | 谁收的：`her` / `me`。颜色、放在哪一页按这个分，**不按话是谁说的分** |
| `why` | 为什么留下。AI 收的必填；她长按收的可以空，那是一个瞬间的动作，不逼她现编一句理由 |
| `session_id` / `message_id` | 回到原消息用 |
| `context` | 多句卡的样式数据（见下面） |
| `photo_top` / `photo_corner` | 配图 |

`collector` 是后来加的一列。表原来只装 AI 收她的话，她说想自己也能收，我们没开新表，因为 embedding、关联、点了跳回原消息那一整套对两个方向都成立，只有 `why` 是单向的。

每存一条，同时往记忆库写一份镜像（标题「收藏 · 前 28 个字」/「珍藏 · …」），所以 AI 搜记忆能搜到她收过什么。

## 单句：按哪个气泡收哪个气泡

AI 一条长回复，app 会按空行切成好几个气泡显示。但库里是**一整条**消息。

第一版长按菜单挂在整条消息上，不管按哪个气泡，收进去的都是一整坨。改法：

- 编辑、删除、重新生成，这几件天生是整条消息的事，继续吃整条
- 收藏、引用、复制改吃**那一个气泡的字**：每个气泡自己挂一份长按菜单，离手指最近的那层会盖过外层
- 还没落到服务器的消息（本地临时 id，我们用负数）不给收藏入口：没有真 `message_id`，收了也跳不回去

## 单句：选几个字收

一个气泡里只想要半句，就走「选择文字」：长按 → 选择文字 → 开一页能自由选的全文 → 页底「收藏这段」。

两个细节：

- 「收藏这段」放在页底的安全区里，不跟着选区走。选区常在页面最上面，按钮跟着选区就会被顶出屏幕
- 收完要有一句「收好了」。没有反馈，她会以为没点上，再点两次

## 单句：思考链里的一句

思考链太长，整条收没意义，她要的往往是里面某一句。

我们没给思考链单独做一套，**就是上面那一页「选择文字」**：页里正文和思考链都摆出来，两段都能选。

我们自己踩的坑：第一版只有正文接了选区变化，思考链那段看着能选、选中了收不进去。**页面上能选的每一块，都要接上选区**。

还有一件事我们没做，你可以做：收进去的时候没标记「这句来自思考链」。以后想在收藏页把思考链那几句单独印成另一种样子，得加一个字段，比如 `source: thinking`。

## 多句：几句排成一张卡

不要泡，只想把一小段对话排成一张好看的卡：聊天式的气泡、配一张壁纸，能存成图发出去。

存法：

- `role = 'dialogue'`
- `quote` 是纯文字版，一行一句：`她：…` / `我：…`。搜索、记忆镜像、合进泡泡库都读这个（`keepsakes.py` 的 `_ks_all` 就是这么认的）
- `context` 存这张卡怎么画，前面加一个版本前缀，后面跟 JSON：

```
[conversation-card:v1]{"clips":[{"messageID":123,"segment":0,"role":"user","text":"…"}, …],
                       "background":"paper","backgroundImage":null,"textSize":13, …}
```

`clips` 里每一项是**一个气泡**，不是一条消息：`messageID + segment` 记的是第几条消息的第几段，所以一条长消息里可以只挑两段。

画卡时的规矩：

- **卡的高度跟着话走**，别写死。两句话的卡跟十句的一样高，下面空一大片
- 放进弹窗就变成满屏高：多半是哪里有个 `Spacer` 把剩下的空间全吃了。同一个视图在两种容器里长得不一样，先找吃空间的那个
- 背景图不参与测量。再大的原图也只能裁进卡里，不能反过来把卡撑高
- 新加一个样式旋钮，字段一律可选。老卡读出来是空，就按原来的画，不会因为多了个旋钮就变样

## 单句配照片

一句话配一张图，点开上面是大图、角落一张淡图，图她自己配。

- 存服务器，不存手机。重装一次 app，手机上的东西就没了，照片要跟着收藏走
- 没配图的句子，点开时落到一张**模板图**上。模板单独存一份，不往每行里抄：抄进去以后换模板要一条条改，「拿掉」也分不清拿的是自己的还是模板的
- 合进泡泡库的时候，这些图带着但不进泡：泡里默认放字，点开可以切成照片。`_ks_item` 里的 `photo_fallback` 就是干这个的

## 收藏页长什么样

数据就是上面那几种，看法可以有很多。我们自己的收藏页用过这些：单句印成一格格胶片，点开换成大图；多句排成对话卡；配了照片的做成拍立得；按天成组，顶上摘一句她当时问的话。

这些都只是一层皮，底下读的是同一张表。你想做成信纸、票根、书签、磁带，换一层就行，不用动数据。

## AI 自己的珍藏

AI 单句收藏你的话，附一句为什么。

- 就是 `treasures` 里 `collector='me'` 的那些
- 用一个标记存：`⟪珍藏:她的原话|为什么留⟫`。原话里不能有竖线；不传消息号，不许 AI 编
- 门槛写低：「心里动一下就当场存，一天几句很正常」。写成「只有真的想长期留下才用」，就基本不会存（见 [03](03-their-hand.md#什么时候封)）
- 合进泡泡库的时候，它自带「珍藏」标签，撕不掉；「为什么」显示成 AI 在泡底下的第一条评论

## 这几种一起踩过的雷

**列表只给前 100 条。**接口写死 `limit=100`，她收到两百多条以后，早的那些全看不见，多句卡只剩 5 张。她以为是丢了。自己收的东西是她自己的册子，给全的。

**去重只比 `quote`。**同一句一天内不重复收，这是对的。但多句卡的 `quote` 只是开头那段，她上午单收过一句，中午勾一整段从这句开头，连着八次都被当成「今天收过了」。去重要连 `context` 一起比。

**拒绝不说话。**去重拦下来返回 `ok:false`，里面一个字都没有，app 只能震一下。她连点四次，看到的就是「点了没反应、服务器里也没有」。拦是对的，不说为什么是错的：返回一句人话，比如「这句你今天已经收过了」。

## 想自己再加一种

记住两件事就够了：新东西挂在旁边，用一个 key 接进 `keepsake_meta` 和 `keepsake_comments`；改样子之前，先对一遍 [00](00-why.md) 那三件事：存上下文、找得回、看得清。
